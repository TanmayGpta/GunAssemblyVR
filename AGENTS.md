# VR Armory (Unity VR gun-assembly trainer)

Namespace `VRArmory`. Main scene `Assets/Scenes/SampleScene.unity`. Unity is driven through the `mcp-unity` tools.

## Workflow
- Scene objects are generated by editor menu items under `Tools/VR Armory/...`; change the builder script, then re-run the menu. Do not hand-edit generated objects.
- After changing `Assets/Editor/Range/RangeSetup.cs` (booth, range menu, FireTraining wiring) run **Tools/VR Armory/Range/2. Setup Range Sergeant**. It destroys and rebuilds `Range_Sergeant` and saves the scene.
- New script files need `Assets/Refresh` before their menu items exist. The MCP connection drops briefly after a refresh or recompile; retry once.
- New `VoiceLine` values go at the END of the enum (`Assets/Scripts/VR/VRVoiceGuide.cs`); scenes store them as numbers.
- Voice clips: text in `VRTrainingText.Spoken`, export with menu `Tools/VR Armory/VR/Export Voice Script`, then in `Tools/VoiceGeneration` run `python generate_voice.py --model-dir models [--only LineA,LineB]`. Output `Assets/Audio/Voice/VO_<line>.wav`. Re-run Setup Range Sergeant so new clips are wired.
- All on-screen and spoken text lives in `Assets/Scripts/VR/VRTrainingText.cs`.

## Gun model (Beretta 92 FS, `Assets/Models/beretta92.fbx`)
- Parts under `ArmorerStation/Staged_Gun_Parts`: `01_Lower_Frame`, `02_Upper_Slide`, `03_Barrel`, `04_Recoil_Spring`, `05_15Rd_Magazine`. Each is an `AssemblyPart`; seating reparents it under the receiving part (slide under frame, barrel and spring under slide), so the assembled gun is one hierarchy under the frame.
- `Assets/Editor/GunModelFix.cs` places pieces and adds `Static_Detail` filler meshes (no collider, no script). Units there: mm, -X = muzzle, +Y = takedown-lever side, +Z = up. At run time use `FunctionCheck.MuzzleLocal` / `UpLocal`.
- The slide mesh is open on top in front and the barrel sits about 1 cm too low, so `Slide_Front_Top` (a filler cylinder) closes it. The FBX has no separate front-slide piece.
- `VRAssemblyGrab.mirrorForRightHand` (set on the magazine) mirrors the grab angle for the right hand.

## Weapon kits (`Assets/Scripts/Assembly/WeaponKit.cs`)
- One `WeaponKit` per gun, on its staged parts group (Beretta: `Staged_Gun_Parts`): steps, function check, frame. `WeaponKitSwitch` (on the manager, runs first) turns the chosen kit on and points the manager, menu, guidance, coach, ghost demo and function-check controls at it. Only one kit is active per scene load; choosing another reloads the scene.
- The menu flow is Modules -> weapon cards -> Briefing -> Training. Cards are built per kit by **Tools/VR Armory/VR/2. Setup VR Scene (additive)**, which also copies `manager.steps` into the Beretta kit. Re-run it after `AssemblySetup` changes the steps, then save the scene.
- Second gun: Intratec TEC-9, `Assets/Models/tec9.fbx` (local only, git-ignored), parts `01_Lower_Frame` .. `06_32Rd_Magazine` (frame has children `Grip_Body`, `Trigger`). Raw download and Blender work files are in `_incoming/` (ignored). Menus: **Tools/VR Armory/TEC-9/1. Setup Model** (materials, import settings), **2. Stage Parts on Bench** (rebuilds `Staged_TEC9_Parts`, sockets, hold point, kit; then runs VR scene setup). Save the scene after.
- TEC-9 steps: bolt -> recoil spring unit -> upper receiver -> takedown pin -> magazine -> function check. `GunPart` gained `Bolt, TakedownPin, UpperReceiver`.
- TEC-9 function check: a second `FunctionCheck` on `Staged_TEC9_Parts` with `hasSafety = false`, `doubleAction = false`, `startCocked`, `slide` = bolt, `rackHandle` = the charging knob. It uses stages 3..6 only (`FirstStage` / `StagesInCheck`), so stage-number consumers (menu, coach, guidance, ghost demo) work unchanged. Per-weapon wording: `VRTrainingText.StageTitle/StageDetail(stage, ..., weaponId)`, coach `Tec9OnBench`, `Tec9_*` voice lines.
- Assembly guidance joins parts in the hands: `VRGuidance.Phase.PickUpHost` highlights the receiving part first; the target ("JOIN HERE") shows only once both are held.
- Range: one live-fire rig per kit (`PistolFiring` + `PistolMagazine`; Beretta on `Range_Live_Fire`, TEC-9 on its child `tec9_Live_Fire`), tuned per weapon in `RangeSetup.SetupFiring`. Finishing an assembly sets `WeaponKit.RangeUnlocked` (PlayerPrefs) for good; the range menu shows every unlocked or currently checked weapon, and `FireTraining.MakeReady` assembles + checks a picked weapon not built this session (other kit: activated and seated via sockets; bench kit: `DebugCompleteAll`, no best time). TEC-9: 32 rounds, no bolt hold-open (rack after every reload), `minShotInterval` 0.2 s, more recoil. Re-run Range 1 then 2 after re-staging TEC-9 parts.
- Hand hold: several thumb values in `VRControllerHands` are in the `VR_Grip_Attach`'s units, and the Beretta's attach has world scale 2.1903. Another gun's attach is given that same world scale (`Tec9ModelSetup.BerettaGripScale`). Fingers wrap meshes named `Grip_*`; the index rests on `Trigger*`. TEC-9 hold point: `HoldBehindMuzzle` / `HoldAboveBottom` in `Tec9ModelSetup.cs`.
- Use mesh-corner bounds in editor builders: `Renderer.bounds` is stale right after objects are created or moved.

## Range (`Assets/Scripts/Range/`)
- `FireTraining` phases: `Off, Choose, Magazine, Load, Ready, Firing, Results`. Live fire only when `FireTraining.LiveFireAllowed` (phase >= Magazine); `PistolFiring` and `PistolMagazine` check it.
- `RangeModeMenu`: weapon -> mode (Unlimited / Timed) -> targets (Stationary / Moving, Timed only). Weapons are `RangeWeapon` entries filled in `RangeSetup.BuildMenu`; the card shows a mesh copy of the weapon.
- Decisions: Timed = count-up timer that ends when the magazine is empty (not a countdown). Unlimited = no timer, magazine refills on insert, always stationary targets, one-time reload voice hint. Targets return to their earlier state after a session. Pistol and magazine are hidden after Finish/End and shown again when a weapon is chosen.
- A second weapon needs its own live-fire setup (firing, magazine, function check, grab), not only a menu entry.
